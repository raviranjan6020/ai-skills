# Docs writing

Write like a careful engineer explaining to a colleague. Short. Precise. Nothing to prove.

## Rules

1. Say the fact, then stop. One idea per sentence. Cut any sentence that repeats the previous one.
2. Lead with what the reader does. Commands first, explanation after, only if needed.
3. Every command must be copy pastable as written. Test it before you write it down.
4. No dashes or semicolons joining clauses. Use a full stop and start a new sentence. Markdown list markers and CLI flags are fine.
5. No filler words: seamlessly, robust, powerful, comprehensive, leverage, delve, elevate, empower, streamline, cutting edge, best in class, unlock, journey, ensure, simply, just, really.
6. No hype adjectives. Do not call anything elegant, blazing, effortless, or world class.
7. No summaries that restate the section. No "In this section we will". No closing "Happy coding".
8. No emoji in docs. No exclamation marks.
9. No "Philosophy" or "Why this matters" sections unless the user asks. State constraints inline where they apply.
10. Tables for comparisons. Lists for steps. Paragraphs for everything else, max three sentences.
11. Headings are nouns or short noun phrases. "Install", not "Getting started with installation".
12. Do not write what the code already says. Link to the file instead.
13. Mark what is untested as untested. Do not imply verification you did not do.

## Before finishing

Read the text once as the reader. Delete every word that can go without losing meaning. Then delete one more.
